# Project steering

These files are always-loaded project rules for people and agents working on autodev. They exist so safety-critical conventions are applied before implementation rather than rediscovered during review.

- `product.md` defines the graded product scope and its hard requirements.
- `security-best-practices.md` defines the trust boundary, secret handling, and subprocess/worktree constraints.
- `dev-best-practices.md` covers project structure, testing, and SDK-first implementation.
- `agent-team.md` assigns specialist roles and routing rules.
- `strands.md` records the Bedrock-only Strands conventions and points to the verified SDK notes.

Treat these as constraints on changes, not as optional background reading.
